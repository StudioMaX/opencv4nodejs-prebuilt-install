# Repository guide

- The package entrypoint is `lib/opencv4nodejs.js`: it loads the native addon through `lib/cv.js`, promisifies methods and adds JS wrappers from `lib/src/`. Native bindings live in `cc/`; public declarations are in `typings/`. When adding a binding, update its C++ registration/implementation and corresponding TypeScript declarations; add new C++ source files to `binding.gyp`.
- Root `tsconfig.json` only compiles the OpenCV build tooling in `build_src_opencv/` to `build_release_opencv/`. Use `npx tsc --noEmit` for a focused check; it does not typecheck the tests or the public API implementation.
- `npm install` runs `prebuild-install || exit 0`: a successful install does not guarantee a usable addon. Runtime loads `build/Release/opencv4nodejs.node` (or `build/Debug` with `BINDINGS_DEBUG`); the package entrypoint catches load failures and exports an undefined value. Set `OPENCV4NODES_DEBUG_REQUIRE=1` to log the underlying load error.
- `npm run create_opencvlib` compiles the build tooling and invokes the OpenCV source builder; it needs Git, CMake and a native toolchain. The committed `opencv4nodejs.disableAutoBuild: 1` causes that builder to skip unless changed. `npm run create_opencvnode_prebuild` compiles the tooling, downloads/unpacks a platform archive from the versioned GitHub release, then runs `prebuild`. Both commands first remove `build_release_opencv`, `opencv`, and extracted platform OpenCV directories; preserve any local data there before running them.
- Tests are a separate package in `test/`, require a working native addon, and import the root through the `@u4/opencv4nodejs` link in `test/package.json`. Its npm lockfile is out of sync with the manifest (which uses `link:..`); do not assume CI's `npm ci` commands currently work unchanged. The suite uses Mocha/ts-node, not root Jest: from `test/`, run `npm test` and `npm run test-externalMemTracking`. For a focused case, use `npx mocha -r ts-node/register --timeout 30000 ./tests/index.test.ts --grep 'pattern'`; most module files export suites rather than standalone tests.
- `TEST_MODULE_LIST` controls the expected OpenCV modules, while individual suites also depend on `cv.modules`; `imgproc` and `objdetect` are explicitly disabled in `test/tests/index.test.ts`. A passing run may therefore cover only a subset of modules.
- CI tests run only on `test4.6.*` tags, not ordinary pushes. Packaging runs `prepack`, which temporarily rewrites `package.json` via `clean-package` and `install/prepublish.js`, followed by `postpack` restoration.
